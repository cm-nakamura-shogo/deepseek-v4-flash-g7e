# DeepSeek V4 Flashの測定結果

## 測定環境

| 項目 | 値 |
| --- | --- |
| EC2 | `g7e.12xlarge` |
| GPU | RTX PRO 6000 Blackwell Server Edition ×2 |
| Model | `nvidia/DeepSeek-V4-Flash-NVFP4` |
| Model Revision | `48bfe38c62be14e8d82f9e3be12fe5d30a2e38c8` |
| Runtime | vLLM 0.26.0 |
| Tensor Parallel | 2 |
| KV Cache | FP8 |
| 出力長 | 256 tokens固定 |
| Prefix Cache | `cache_salt`によりリクエスト間の再利用を防止 |

各条件で2 roundsのwarm-upを実行し、その後の5 roundsを集計しました。

## CUDA Graph

初期構成とCUDA Graphの比較では、短い日本語プロンプトを1並列で実行しました。

| 構成 | E2E output tok/sec | Decode output tok/sec | TTFT中央値 |
| --- | ---: | ---: | ---: |
| vLLM 0.25.0、Eager | 10.39 | 10.40 | 110.0ms |
| vLLM 0.26.0、Eager | 9.77 | 9.77 | 115.8ms |
| vLLM 0.26.0、Decode用CUDA Graph | 103.95 | 108.59 | 114.3ms |

Decode用CUDA Graphにより、単一リクエストの生成速度はEager実行の約10倍になりました。

## 入力長と並列数

この測定では合成プロンプトをvLLMの`/tokenize`で調整し、MTPを無効にしました。

| 実入力tokens | 並列数 | Aggregate output tok/sec | 1リクエストE2E output tok/sec | TTFT中央値 |
| ---: | ---: | ---: | ---: | ---: |
| 254 | 1 | 102.67 | 102.69 | 112.9ms |
| 254 | 2 | 169.88 | 85.34 | 171.6ms |
| 254 | 4 | 297.09 | 74.62 | 229.6ms |
| 2,046 | 1 | 98.82 | 98.84 | 182.6ms |
| 2,046 | 2 | 161.64 | 81.08 | 272.4ms |
| 2,046 | 4 | 261.72 | 65.74 | 444.5ms |
| 8,185 | 1 | 83.02 | 83.03 | 691.8ms |
| 8,185 | 2 | 123.73 | 62.05 | 1,029.2ms |
| 8,185 | 4 | 172.28 | 43.46 | 1,702.6ms |

短文では並列数を1から4へ増やすとAggregate output tok/secが約2.89倍になりました。
一方、GPUリソースを共有するため、1リクエスト当たりのE2E output tok/secは低下しました。

## Prefillのバッチ上限

8K入力、4並列で`max-num-batched-tokens`を比較しました。

| `max-num-batched-tokens` | TTFT中央値 | Aggregate output tok/sec |
| ---: | ---: | ---: |
| 2,048 | 1,702.6ms | 172.28 |
| 4,096 | 1,568.4ms | 178.30 |
| 8,192 | 1,537.7ms | 180.49 |
| 16,384 | 1,812.1ms | 181.45 |

8K条件だけでは8,192が最短TTFTでしたが、2K入力を含む条件間のバランスから4,096を採用しました。

## MTP

MTP=1は、定型文を繰り返した予測しやすい入力で測定しました。
自然対話や複雑な推論では採択率が変わるため、同じ改善率を保証する結果ではありません。

| 実入力tokens | 並列数 | MTPなし Aggregate output tok/sec | MTP=1 Aggregate output tok/sec | 改善率 |
| ---: | ---: | ---: | ---: | ---: |
| 254 | 1 | 102.58 | 135.55 | +32.1% |
| 254 | 2 | 171.37 | 227.95 | +33.0% |
| 254 | 4 | 298.69 | 358.41 | +20.0% |
| 2,046 | 1 | 98.87 | 128.59 | +30.1% |
| 2,046 | 2 | 163.54 | 213.32 | +30.4% |
| 2,046 | 4 | 264.94 | 330.29 | +24.7% |
| 8,185 | 1 | 85.04 | 106.80 | +25.6% |
| 8,185 | 2 | 126.60 | 151.89 | +20.0% |
| 8,185 | 4 | 178.91 | 202.11 | +13.0% |

MTP=1の採択率は約65%から67%でした。
MTP用のCUDA Graph capture sizeに8を含めない場合、4並列でEager実行へフォールバックするため、Terraformでは並列数と投機token数からcapture sizeを組み立てています。

## 比較時の注意

初期構成とCUDA Graphの比較は短い日本語プロンプトを使用しています。
入力長、並列数、MTPの比較は254 tokensなどへ調整した合成プロンプトを使用しています。
したがって、すべての表を単一の同一入力条件による連続比較として扱うことはできません。
